# Qualitative SEC filing evidence

The SEC ingestor extracts risk-factor and management's discussion and analysis (MD&A) text from the same saved filing document used for the source checksum. The normalized text is an excerpt, never a model summary. A content-addressed `.excerpts.json` artifact records the document checksum, filing form, sections, normalized line numbers/character offsets, omitted-character counts and unavailable sections. New filing manifests reference this artifact beside the original document and accession-filtered XBRL facts.

Each section includes at most **3,200 characters**, clipped at a nearby word boundary, with an explicit count of text omitted after the excerpt. The extractor supports Item 1A and Item 7 for 10-K filings, and Item 1A and Item 2 for 10-Q filings. It strips comments, scripts/styles, hidden elements and inline-XBRL hidden metadata; decodes common/numeric entities; and preserves block boundaries for heading detection. It rejects contents entries containing page numbers and ends the section at the next differently numbered item. When headings repeat, it chooses the longest substantive candidate. Files over 30 MiB, unsupported forms, unrecognized headings and sections shorter than 80 characters produce explicit missing-section results.

Analyst and skeptic workers enrich source rows from verified artifacts under `SEC_ARTIFACT_DIR` (default `~/.local/share/quant-swarm/artifacts/sec`). Both ingestors and research workers must use the same artifact directory, or mount a shared copy with the same layout. Reads are bounded, limited to content-addressed filenames in that directory, and reject file symlinks. Manifest hash, document/source URI, symbol, form and checksum must match; excerpt files must match both their own filename hash and the manifest reference. Missing or invalid artifacts yield an explicit unavailable-evidence notice. Nothing reads arbitrary paths from the database into a model prompt.

Existing source rows keep their original immutable manifest references when ingestion is repeated. For these legacy manifests, workers derive excerpts from the verified saved filing document. No database migration or source-ID replacement is required. New sources load the precomputed excerpt artifact. An unchanged source ID remains the citation for its excerpt; the richer excerpt is cited by its source ID. In addition, each found section records at most two deterministic `excerpt.<section>` fact chunks (240 characters each, `unit=text`, filing report date, `ok`/`heuristic` quality). This stays inside the module’s 256-character fact-value limit. Manifests record chunk IDs, offsets and checksums; `recordId` keeps long IDs bounded and reruns insert no duplicates.

The existing shared evidence selection includes excerpt text when checking its 30,000-character evidence and 48,000-character overall prompt bounds. Including a filing continues to include all its facts. Prompts label the source, section, normalized line span, truncation and missing sections. Rules workers use the same selected evidence; model workers receive the text for both analyst and skeptic calls. The coordinator continues to consume the stored thesis and skeptic challenge.

Heading extraction is heuristic. It does not cover every filing layout, attachments, incorporated-by-reference text, or the full qualitative discussion. Missing sections and omitted text should lead to an explicit research limitation rather than an invented conclusion. Normalized line numbers refer to the text conversion, not HTML file line numbers. Qualitative excerpt availability does not prove source freshness or complete evidence coverage.

An offline smoke check also found both sections in the four saved AAPL/MSFT 10-K/10-Q documents; no live download or inference is needed for these checks.

Run `npm run build` then `node scripts/check-sec-ingest.ts [existing-artifact-directory]` for live isolated-database ingestion with the previously saved AAPL/MSFT document/XBRL artifacts replayed locally. It checks four sources/16 excerpt facts, interrupts after AAPL, recovers the partial ingestion, and proves a third run changes no rows. Network interception allows only the temporary database’s token exchange; SEC responses are replayed and no provider or broker calls occur. This verifies stored data/reducers and does not claim a new live SEC download. Fresh SEC acceptance requires a real `SEC_USER_AGENT` contact.

Trimmed real AAPL 10-K/10-Q visible-text fixtures in `fixtures/sec/` retain source URI and original document checksum; their HTML wrappers/contents rows are fixture formatting. Full filings are not committed. New inference records use prompt version `research-v3-sec-excerpts`; completed work still reuses its prior audited output.
