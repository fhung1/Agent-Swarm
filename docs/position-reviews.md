# Held paper position reviews

Enable with `"positionReviews": { "everyDays": 30, "priceMovePct": 10 }` in the swarm config. The setting requires coordinator, analyst and skeptic workers. The coordinator gets explicit read access to the configured paper account but no broker credentials. It scans every 15 seconds and on subscribed snapshot, fill, fact and quote updates; a paused run queues nothing.

The coordinator considers a position only when a buy proposal has a recorded paper order and fill, the account snapshot is active and at most 15 minutes old, and the current position quantity matches recorded buy and sell fills. Sell fills consume earlier buy lots first. This prevents an old, closed buy from being linked to a later position in the same symbol. An account mismatch or external position yields no automatic review until reconciled.

Each held lot can create one pending review task at a time. In priority order, signals are position value above the current policy's position cap, a new SEC `filing_update_review` marker ingested after the first fill, a fresh bid at least `priceMovePct` from the weighted fill price, a newly recorded fill, and each `everyDays` cycle after the first fill. Task IDs are derived from the proposal and trigger, so restarts and repeated snapshots do not duplicate work. A repeated price or policy breach can create at most one task per UTC day. Completed tasks remain in the audit history; a new distinct signal can create the next task.

A review task depends on the original thesis task. The analyst sees the original thesis and current selected evidence and publishes a new thesis. The skeptic and optional valuation/portfolio workers use the same review flow as an entry thesis. The coordinator treats `abstain` as hold; it may propose only a sell exit, and the separate deterministic risk gate checks current shares, account, policy, market and quote before paper execution. Rule-based analysis does not fabricate an exit. The model may interpret the original thesis invalidation text, but this service does not claim to parse arbitrary text into a deterministic trigger.

This is an automatic paper-trading path with no per-order approval. It does not handle corporate actions or symbol changes; the separate `trading-corporate-actions` board task owns that reconciliation gate. The dependent live acceptance tasks must verify the flow with a real paper account and current market data.
