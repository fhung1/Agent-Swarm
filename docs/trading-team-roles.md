# Optional trading team roles

Set `agents.valuation.count` and/or `agents.portfolio.count` above zero in the swarm config. Both default to zero for existing runs. They require an analyst and coordinator. Each worker has a separate database identity and claims a role-scoped task after the thesis task completes. The coordinator waits for each configured specialist task to complete or fail before it queues skeptic review.

The valuation role produces a typed `valuation` message with bear, base and bull per-share values, assumptions, risks and cited evidence IDs. A ready report requires positive, ordered values and stored citations. Missing valuation inputs become an `insufficient` report with no numeric targets. The portfolio role receives a grant for the configured paper account and reads its latest scoped snapshot and risk policy. It reports exposure, liquidity, concentration and a recommendation in a typed `portfolio` message. A missing or older-than-15-minute snapshot produces an `insufficient` report without a model call. The portfolio process receives a model secret if needed, but no Alpaca key or secret.

Messages have stable IDs derived from the task and cite the thesis. The module permits specialist messages only from an authenticated worker holding the matching live task lease, and validates report evidence and ready-state inputs. The skeptic reads completed reports; the coordinator freezes their message IDs with challenge IDs in its decision input. A configured report that is missing or insufficient prevents a model trade recommendation and yields `revise`. All proposed trades still go through the separate deterministic risk gate before paper execution. A rules-based specialist deliberately reports `insufficient`; it does not synthesize a valuation or account assessment.

Use `npm run swarm -- plan`, `register`, `grant`, and `start` with the normal supervisor flow. Granting the portfolio worker requires an account ID. This change does not publish or migrate the live trading database; publish the updated module and regenerate bindings as part of the normal deployment process before enabling the new role counts.
